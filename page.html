01 / 개관

학기의 큰 그림

2학기 전체가 세 단계로 이어집니다. 뒤 단계는 앞 단계 위에서만 성립하므로, 한 단계를 놓치면 다음이 무너집니다.

STEP 1 · 2~3주

구조를 바꾼다

배열과 리스트로는 “A와 B가 연결되어 있다”를 표현할 수 없습니다. 트리와 그래프로 관계 자체를 자료구조에 담습니다.

STEP 2 · 4~6주

순서를 만든다

찾아낸 결과를 사용자에게 보여 주려면 순서가 필요합니다. 정렬 알고리즘을 원리와 시간 복잡도로 비교해 고릅니다.

STEP 3 · 7~9주

빠르게 찾는다

자료가 많아지면 전부 확인할 수 없습니다. 이진 탐색과 해싱으로 찾는 비용을 줄이는 방법을 배웁니다.

1학기와 어떻게 이어지는가

1학기에 배운 배열·스택·큐·연결 리스트는 모두 한 줄로 이어진 구조였습니다. 2학기 첫 수행평가가 “배열로 처리하면 무엇이 문제인가”를 묻는 이유가 여기에 있습니다. 1학기 내용을 다시 꺼내 쓸 일이 많으니, 스택과 큐의 동작만은 확실히 기억해 두세요. 그래프 탐색에서 그대로 쓰입니다.

수업과 AI 활용 규칙

해도 되는 것

  • 자료 검색과 전문 자료의 요약
  • 아이디어와 비교표를 여러 개 받아 보기
  • 내가 쓴 글의 사실관계 확인받기
  • 내 논리에서 빠진 부분을 지적받기

하면 안 되는 것

  • AI가 써 준 문장을 그대로 옮겨 적기
  • 항목 전체를 통째로 대신 작성시키기
  • 사실 확인 없이 AI 설명을 그대로 믿기
  • 출처와 AI 활용 범위를 밝히지 않기
결과물 산출에 AI를 활용한 내용을 그대로 작성할 경우, 해당 평가 요소의 최하점이 부여됩니다. 수행평가 1 안내 페이지에 규정을 지키면서 AI를 제대로 쓰는 프롬프트 7종을 올려 두었습니다. 그대로 복사해서 쓰면 안전합니다.

  • 채점기준표는 평가 전에 반드시 공개합니다. 기준을 모르고 평가받는 일은 없습니다.
  • 결과는 실시 후 개별 통지하며, 공개일 포함 3일간(공휴일 제외) 이의신청할 수 있습니다.
  • 미도달 학생에게는 피드백 후 1회 보완 제출 기회를 줍니다(최대 C수준 인정).

정렬이란

자료를 일정 순서대로 나열하는 것

물건을 크기 순으로 오름차순이나 내림차순으로 나열하는 것. 정렬은 컴퓨터공학을 포함한 모든 과학기술 분야에서 가장 기본적이고 중요한 알고리즘 중 하나입니다. 자료 탐색에 있어서 필수적이기 때문입니다.

정렬의 대상

레코드와 키(key)

일반적으로 정렬시켜야 될 대상은 레코드(record)입니다. 레코드는 필드라는 더 작은 단위로 구성되고, 그중 키(key) 필드로 레코드와 레코드를 구별합니다.

어떤 정렬을 골라야 할까

모든 경우에 최적인 정렬 알고리즘은 없습니다. 따라서 각 응용 분야에 적합한 정렬 방법을 사용해야 합니다. 고를 때의 기준은 두 가지입니다 — 비교 횟수와 이동 횟수.

단순하지만 비효율적인 방법

선택 정렬SELECTION SORT

O(n²)

초기에는 왼쪽 리스트는 비어 있고, 정렬할 숫자들은 모두 오른쪽 리스트에 존재합니다. 오른쪽에서 가장 작은 값을 골라(select) 왼쪽 끝에 붙이는 것을 반복합니다.

키 순서로 줄 세우기

반 전체를 키 순서로 세운다고 해 봅시다. “제일 작은 사람 손 들어!” 하고 찾아서 맨 앞에 세웁니다. 그다음 남은 사람 중에 제일 작은 사람을 찾아 두 번째에 세웁니다. 이걸 계속 반복하면 끝납니다.

쭉 훑어서 제일 작은 걸 찾고 → 맨 앞자리와 자리 바꾸기 → 반복

수업 슬라이드 원문 · C

#define SWAP(x, y, t) ( (t)=(x), (x)=(y), (y)=(t) )

void selection_sort(int list[], int n) {
    int i, j, least, temp;
    for(i=0; i<n-1; i++) {
        least = i;
        for(j=i+1; j<n; j++)    // 최솟값 탐색
            if(list[j]<list[least]) least = j;
        SWAP(list[i], list[least], temp);
    }
}
least = i; “일단 i번 자리에 있는 애가 제일 작다고 생각해 두자.”
for(j=i+1; j<n; j++) “뒤에 있는 애들을 한 명씩 다 쳐다본다.”
if(list[j]<list[least]) least = j; “어? 얘가 더 작네. 제일 작은 애를 얘로 바꿔 기억해 두자.” — 아직 자리는 안 바꿉니다.
SWAP(list[i], list[least], temp); 다 훑어봤으니 진짜 제일 작은 애와 i번 자리를 딱 한 번 바꿉니다.
핵심 안쪽 for문은 제일 작은 애가 어디 있는지 위치만 기억하고, 자리 바꾸기는 바깥에서 딱 한 번만 합니다. 그래서 쳐다보는 횟수는 많아도 자리를 바꾸는 횟수는 가장 적습니다. 시뮬레이터로 학습지 ① 자료를 돌리면 교환이 3번밖에 안 됩니다.

삽입 정렬INSERTION SORT

O(n²)

정렬되어 있는 부분에 새로운 레코드를 올바른 위치에 삽입하는 과정을 반복합니다.

카드 게임에서 카드 정리하기

카드를 칠 때 새 카드를 한 장 받으면 어떻게 하나요? 손에 이미 정리된 카드들 사이 알맞은 자리에 쏙 끼워 넣죠. 끼워 넣으려면 그 자리보다 큰 카드들을 오른쪽으로 한 칸씩 밀어야 합니다. 그게 전부입니다.

새 카드 뽑기 → 자기보다 큰 카드들을 오른쪽으로 밀기 → 생긴 빈자리에 끼우기

수업 슬라이드 원문 · C

void insertion_sort(int list[], int n)
{
    int i, j, key;
    for(i=1; i<n; i++){
        key = list[i];
        for(j=i-1; j>=0 && list[j]>key; j--)
            list[j+1] = list[j];
        list[j+1] = key;
   }
}
key = list[i]; “이번에 손에 쥔 새 카드는 이거야.” — 원래 자리는 잠시 비워 둡니다.
j = i-1 “바로 왼쪽 카드부터 살펴보자.”
list[j] > key “왼쪽 카드가 내 카드보다 크네? 그럼 자리를 비켜 줘야 해.”
list[j+1] = list[j]; 큰 카드를 오른쪽으로 한 칸 민다. (맞바꾸는 게 아니라 미는 것)
list[j+1] = key; 더 밀 필요가 없어졌으니 생긴 빈자리에 내 카드를 쏙 넣는다.
핵심 list[j]>key 가 거짓이 되는 순간 바로 멈춥니다. 즉 이미 순서가 맞으면 한 번도 밀지 않습니다. 그래서 거의 정렬된 자료에서는 O(n) 에 가까워집니다. 시뮬레이터로 학습지 ③(4 5 9 3 6 8 7 1) 앞부분이 후루룩 지나가는 걸 확인해 보세요.

버블 정렬BUBBLE SORT

O(n²)

인접한 2개의 레코드를 비교하여 순서대로 되어 있지 않으면 서로 교환합니다.

옆 사람이랑만 키 재기

줄을 선 채로 바로 옆 사람하고만 키를 비교합니다. 내가 더 크면 한 칸 뒤로 물러납니다. 왼쪽 끝에서 오른쪽 끝까지 한 번 훑으면 가장 큰 사람이 맨 뒤에 가 있습니다. 그 사람은 확정. 다시 처음부터 반복하면 두 번째로 큰 사람이 확정됩니다.

큰 값이 거품(bubble)처럼 뒤로 뽀글뽀글 떠오른다고 해서 버블 정렬

수업 슬라이드 원문 · C

void bubble_sort(int list[], int n)
{
    int i, j, temp;
    for(i=n-1; i>0; i--){
        for(j=0; j<i; j++)
           if(list[j]>list[j+1])
               SWAP(list[j], list[j+1], temp);
   }
}
for(i=n-1; i>0; i--) “몇 번째 자리까지 확정됐나를 세는 바깥 반복. 뒤에서부터 하나씩 확정됩니다.”
for(j=0; j<i; j++) “왼쪽 끝부터 아직 확정 안 된 곳까지만 훑는다.” — 확정된 뒤쪽은 볼 필요 없습니다.
if(list[j]>list[j+1]) “나랑 바로 오른쪽 사람만 비교. 내가 더 크면?”
SWAP(list[j], list[j+1], temp); “바로 자리를 바꾼다.” — 볼 때마다 바꾸니까 교환이 많아집니다.
핵심 선택 정렬은 다 보고 나서 한 번만 바꾸는데, 버블 정렬은 볼 때마다 바꿉니다. 같은 자료(학습지 ①)로 돌려 보면 선택 정렬은 교환 3번, 버블 정렬은 15번입니다. 비교 횟수는 둘 다 28번으로 똑같습니다.

셸 정렬SHELL SORT

O(n^1.5)

전체 리스트를 일정 간격(gap)의 부분 리스트로 나눈 후, 나뉜 각각의 부분 리스트를 삽입 정렬합니다. 간격을 절반씩 줄여 가며 반복합니다.

멀리 있는 것부터 대충 옮겨 놓기

삽입 정렬은 값을 한 칸씩만 밀 수 있습니다. 그래서 맨 뒤에 있어야 할 큰 값이 맨 앞에 있으면 일곱 칸을 하나하나 밀어야 합니다. 너무 느리죠.

셸 정렬은 먼저 멀리(자료가 8개면 5칸씩) 떨어진 것끼리만 비교해 대충 정리하고, 그다음 3칸씩, 마지막에 1칸씩 합니다. 큰 값은 미리 뒤로, 작은 값은 미리 앞으로 보내 두기 때문에 마지막 1칸 삽입 정렬은 거의 할 일이 없습니다.

방 치울 때 물건을 구역별로 대충 던져 놓고 나서 정리하는 것과 같습니다.

코드는 생략합니다 셸 정렬의 코드는 삽입 정렬과 사실상 같습니다. j-- 가 j -= gap 으로 바뀐 것 하나뿐입니다. 코드를 외우기보다 부분 리스트가 어떻게 묶이는지를 눈으로 익히세요.

직접 보기

자료 8개면 gap이 5 → 3 → 1 로 좁아집니다. 간격 5일 때는 5줄, 3일 때는 3줄의 부분 리스트가 생깁니다. 각 줄이 색으로 구분되어 표로 나타납니다 — 수업 자료의 그 표와 같은 형식입니다.

5

퀵 정렬QUICK SORT

평균 O(n log n)

평균적으로 가장 빠른 정렬 방법입니다. 분할정복법을 사용하여 리스트를 2개의 부분 리스트로 비균등 분할하고, 각각의 부분 리스트를 다시 퀵 정렬(재귀호출)합니다.

반장 뽑아서 왼쪽·오른쪽으로 갈라 세우기

학생 8명을 키 순으로 세워야 합니다. 한꺼번에 하려니 막막하죠. 그래서 아무나 한 명을 기준(피벗)으로 정합니다. 예를 들어 맨 앞 사람.

그리고 이렇게 외칩니다. “나보다 작은 사람은 내 왼쪽, 큰 사람은 내 오른쪽!” 이러면 기준이 된 사람은 자기 자리를 정확히 찾은 겁니다. 왼쪽에 3명, 오른쪽에 4명이 있으면 자기는 4번째 자리인 게 확실하니까요.

이제 왼쪽 3명끼리 또 똑같이, 오른쪽 4명끼리 또 똑같이 하면 됩니다. 무리가 1명이 될 때까지 계속 쪼개면 끝납니다.

기준 한 명 정하기 → 작은 쪽·큰 쪽으로 갈라 세우기 → 기준은 자리 확정 → 양쪽에서 또 반복

헷갈리는 부분만 따로 — low 와 high 는 뭘 하나요?

퀵 정렬이 어려운 이유는 partition 함수 안에서 손가락 두 개(low, high)가 서로 마주 보고 걸어오기 때문입니다. 이것만 이해하면 끝납니다.

양쪽에서 손가락 두 개가 걸어온다

왼손(low) 은 왼쪽 끝에서 오른쪽으로 걸어오면서 “피벗보다 큰 애” 를 찾으면 멈춥니다. — 얘는 오른쪽으로 가야 하는데 왼쪽에 있네?

오른손(high) 은 오른쪽 끝에서 왼쪽으로 걸어오면서 “피벗보다 작은 애” 를 찾으면 멈춥니다. — 얘는 왼쪽으로 가야 하는데 오른쪽에 있네?

둘 다 멈췄으면 둘이 자리를 바꿉니다. 잘못된 자리에 있던 둘이 서로 제자리를 찾아가는 거죠. 이걸 반복하다가 두 손이 서로 엇갈리면(왼손이 오른손을 지나치면) 가르기가 끝난 겁니다.

마지막으로 피벗을 오른손이 멈춘 자리에 넣어 줍니다. 그 자리가 피벗의 진짜 자리입니다.

피벗을 정한다 맨 왼쪽 값을 피벗으로 삼습니다. 여기서는 5. 5 3 8 4 9 1 7 6
왼손이 걸어온다 왼쪽부터 “5보다 큰 애”를 찾습니다. 3은 작으니 통과, 8에서 멈춤. 5 3 8 4 9 1 7 6  ← low
오른손이 걸어온다 오른쪽부터 “5보다 작은 애”를 찾습니다. 6·7·9는 크니 통과, 1에서 멈춤. 5 3 8 4 9 1 7 6  high →
둘을 맞바꾼다 왼쪽에 있으면 안 되는 8과, 오른쪽에 있으면 안 되는 1을 교환합니다. 5 3 1 4 9 8 7 6
다시 걸어오다 엇갈린다 왼손은 9에서, 오른손은 4에서 멈춥니다. 그런데 왼손(4번)이 오른손(3번)을 지나쳤습니다. 엇갈렸으니 가르기 끝. 5 3 1 4 9 8 7 6
피벗을 제자리에 피벗 5와, 오른손이 멈춘 자리의 4를 바꿉니다. 이제 5의 왼쪽은 모두 작고 오른쪽은 모두 큽니다. 5는 영원히 확정입니다. 4 3 1 5 9 8 7 6
양쪽에서 똑같이 반복 왼쪽 묶음 [4 3 1] 과 오른쪽 묶음 [9 8 7 6] 에 대해 1~6번을 처음부터 다시 합니다. 이것이 재귀호출입니다.
딱 세 가지만 기억하세요 ① 피벗은 한 번 자리를 잡으면 다시 안 움직인다. ② 왼손은 큰 애를, 오른손은 작은 애를 찾는다. ③ 엇갈리면 가르기 끝, 피벗을 오른손 자리에 넣는다.

코드로 보기

수업 슬라이드 원문 · C

int partition(int list[], int left, int right) {
   int pivot, temp, low, high;
   low = left;
   high = right+1;
   pivot = list[left];
   do {
            do
                low++;
            while(low<=right && list[low]<pivot);
            do
                high--;
            while(high>=left && list[high]>pivot);
            if(low<high) SWAP(list[low], list[high], temp);
   } while(low<high);
슬라이드가 여기서 끝납니다 수업 자료의 코드는 } while(low<high); 까지만 실려 있습니다. 가르기가 끝난 뒤에는 피벗을 오른손이 멈춘 자리로 옮기고, 그 위치를 돌려주는 마무리가 더 필요합니다. 그리고 그 위치를 기준으로 왼쪽 구간과 오른쪽 구간을 각각 다시 퀵 정렬합니다. 시뮬레이터의 마지막 두 단계가 정확히 그 부분입니다.
pivot = list[left]; “맨 왼쪽 애를 기준(피벗)으로 삼는다.”
low = left; high = right+1; 왼손은 왼쪽 끝, 오른손은 오른쪽 끝 바로 바깥에 둡니다. 곧바로 low++ / high-- 로 한 칸씩 들어오기 때문입니다.
do low++; while(list[low]<pivot); “왼손아, 피벗보다 작은 애는 그냥 지나쳐. 큰 애를 만나면 멈춰.”
do high--; while(list[high]>pivot); “오른손아, 피벗보다 큰 애는 그냥 지나쳐. 작은 애를 만나면 멈춰.”
if(low<high) SWAP(...) “아직 안 엇갈렸으면 둘이 자리를 바꿔.”
} while(low<high); “엇갈릴 때까지 계속 반복.”
SWAP(list[left], list[high], temp); “피벗을 오른손이 멈춘 자리로 옮긴다.” — 여기가 피벗의 최종 자리입니다.
return high; “피벗이 어디 놓였는지 알려 준다.” 이 위치를 기준으로 좌우를 다시 정렬합니다.
왜 최악이 O(n²) 인가 이미 정렬된 자료에 맨 왼쪽을 피벗으로 쓰면, 피벗보다 작은 애가 하나도 없습니다. 그러면 한 명과 나머지 전부로 갈라져서, 반씩 줄어드는 이점이 사라집니다. 그래서 학습지 3번처럼 왼쪽·중간·오른쪽의 중간값을 피벗으로 고르는 방법을 씁니다.

합병 정렬MERGE SORT

O(n log n)

리스트를 두 개의 균등한 크기로 분할하고, 분할된 부분 리스트를 정렬한 다음, 정렬된 두 개의 부분 리스트를 합하여 전체 리스트를 정렬합니다.

두 줄로 선 사람들을 한 줄로 합치기

이미 키 순으로 정렬된 두 줄이 있다고 해 봅시다. 이 둘을 한 줄로 합치는 건 아주 쉽습니다. 두 줄의 맨 앞 사람만 비교해서 더 작은 쪽을 데려오면 됩니다. 그걸 계속하면 끝납니다. 뒤쪽은 볼 필요도 없어요.

그럼 처음부터 정렬된 두 줄은 어디서 구하죠? 반으로 쪼개서 각각을 또 이 방법으로 정렬하면 됩니다. 계속 쪼개다 보면 결국 한 명짜리 줄이 되는데, 한 명은 이미 정렬된 상태죠. 거기서부터 합쳐 올라옵니다.

끝까지 반씩 쪼갠다 → 한 명이 되면 멈춘다 → 둘씩 짝지어 합치며 올라온다

  • 분할 — 배열을 같은 크기의 2개 부분 배열로 나눈다.
  • 정복 — 부분 배열을 정렬한다. 크기가 충분히 작지 않으면 재귀호출로 다시 분할정복을 적용한다.
  • 결합 — 정렬된 부분 배열을 하나의 배열로 통합한다.

퀵 정렬과 뭐가 다른가 퀵 정렬은 피벗 기준으로 비균등 하게 자르고, 합병 정렬은 무조건 가운데에서 자릅니다. 그래서 합병 정렬은 자료가 어떻게 생겼든 항상 O(n log n) 을 보장합니다. 대신 합칠 때 여분의 배열이 필요해 메모리를 더 씁니다. 시뮬레이터에서 합병 정렬을 골라 쪼개는 단계와 합치는 단계를 눈으로 보세요.
7

기수 정렬RADIX SORT

O(d·n)

지금까지의 정렬은 모두 값끼리 비교했습니다. 기수 정렬은 비교를 한 번도 하지 않습니다. 대신 자릿수(radix)만 보고 바구니에 나눠 담았다가 순서대로 꺼냅니다.

번호표 순서로 줄 세우기

학생들이 두 자리 번호표를 달고 있습니다. 이름표를 비교하지 않고 줄을 세우는 법이 있습니다.

먼저 1의 자리만 봅니다. 0번 바구니부터 9번 바구니까지 놓고, 번호 끝자리가 8이면 8번 바구니에 넣습니다. 다 넣었으면 0번 바구니부터 순서대로 꺼내 다시 줄을 세웁니다.

그다음 10의 자리만 봅니다. 똑같이 바구니에 넣었다 꺼냅니다. 놀랍게도 이것만으로 완전히 정렬됩니다. 1의 자리로 이미 정렬해 뒀기 때문에, 10의 자리가 같은 애들끼리는 순서가 그대로 유지되거든요.

자릿수가 d개면 바구니에 넣었다 꺼내는 걸 d번 → 그래서 O(d·n)

확인 문제

Q1 같은 자료를 선택 정렬과 버블 정렬로 각각 돌리면, 교환 횟수는 어느 쪽이 더 많을까? 그 이유는?

버블 정렬이 훨씬 많습니다. 버블 정렬은 이웃을 비교할 때마다 곧바로 교환하지만, 선택 정렬은 안쪽 반복에서 최솟값의 위치만 기억해 두었다가 바깥 반복마다 딱 한 번만 교환하기 때문입니다. 비교 횟수는 둘 다 약 n²/2 로 비슷합니다.

Q2 이미 오름차순으로 정렬된 배열에 삽입 정렬을 적용하면 시간 복잡도는 어떻게 될까?

O(n) 이 됩니다. 안쪽 for문의 조건 list[j]>key 가 첫 비교에서 바로 거짓이 되어 한 번도 밀지 않고 빠져나오기 때문입니다. 바깥 for문만 n−1번 도는 셈이라 삽입 정렬은 거의 정렬된 자료에서 가장 유리한 알고리즘입니다.

Q3 퀵 정렬에서 이미 정렬된 배열에 대해 맨 왼쪽 원소를 피벗으로 고르면 어떤 일이 생길까?

피벗보다 작은 값이 하나도 없어서 분할이 1개와 n−1개로 극단적으로 치우칩니다. 이 상태가 매번 반복되어 재귀 깊이가 n이 되고, 결과적으로 최악의 경우 O(n²) 가 됩니다. 그래서 정렬 학습지 3번처럼 왼쪽·중간·오른쪽의 중간값을 피벗으로 고르는 방법을 씁니다.

Q4 셸 정렬에서 간격(gap)을 두는 이유는 무엇일까?

삽입 정렬은 값을 한 칸씩만 옮기기 때문에, 멀리 떨어진 곳에 있어야 할 값이 제자리를 찾으려면 아주 많이 움직여야 합니다. 셸 정렬은 gap칸씩 건너뛰며 미리 대충 자리를 잡아 두어 이 이동량을 크게 줄입니다. 마지막에 gap=1 로 삽입 정렬을 하면 이미 거의 정렬된 상태라 금방 끝납니다.

Q5 정렬 알고리즘을 고를 때의 두 가지 기준은 무엇인가?

비교 횟수와 이동(교환) 횟수입니다. 자료 하나의 크기가 크면 옮기는 비용이 커지므로 이동 횟수가 적은 선택 정렬이 유리할 수 있고, 비교 자체가 비싸면 비교 횟수가 적은 쪽이 유리합니다. 모든 경우에 최적인 정렬 알고리즘은 없습니다.

순차 탐색의 for문은 매번 두 가지를 확인합니다. “끝까지 왔나?” 와 “찾는 값인가?”. 이 중 하나를 없애는 방법이 있습니다.

찾는 값을 미리 맨 뒤에 놓아 둔다

줄 맨 끝에 찾는 값을 하나 몰래 세워 둡니다. 그러면 무슨 일이 생길까요? 반드시 찾게 됩니다. 진짜로 있으면 중간에서 만나고, 없으면 맨 끝에 세워 둔 그 가짜를 만나죠.

덕분에 “끝까지 왔나?” 를 매번 확인할 필요가 없어집니다. 멈춘 자리가 맨 끝이면 ‘없음’, 중간이면 ‘찾음’. 비교 조건이 하나 줄어드니 조금 더 빨라집니다.

슬라이드 예제 — 9 5 8 3 7 에서 찾기

8을 찾는 경우 (1) 9≠8 계속 → (2) 5≠8 계속 → (3) 8=8 탐색 성공
2를 찾는 경우 (1)~(5) 9, 5, 8, 3, 7 모두 다름 → (6) 2=2 이지만 마지막 항목이므로 탐색 실패
핵심 맨 끝에서 만난 값은 내가 심어 둔 가짜입니다. 그래서 ‘찾았다’가 아니라 ‘없다’ 로 판정합니다.

이진 탐색BINARY SEARCH

O(log n)

정렬된 배열의 중앙에 있는 값을 조사하여, 찾고자 하는 항목이 왼쪽 또는 오른쪽 부분 배열에 있는지를 알아내어 탐색의 범위를 반으로 줄여 가며 진행합니다.

업다운 게임

1부터 100 사이 숫자 맞히기 게임을 생각해 보세요. 무작정 1, 2, 3… 부르는 사람은 없습니다. 50을 부르고 “업!” 이면 1~50은 통째로 버립니다. 한 번 물어볼 때마다 후보가 절반으로 줄어들죠.

100개 → 50 → 25 → 13 → 7 → 4 → 2 → 1. 7번이면 끝납니다. 10억 개도 30번이면 됩니다. 이게 O(log n) 입니다.

단, 게임 규칙이 ‘업/다운’이려면 숫자가 순서대로 있어야 합니다 — 정렬이 필수인 이유

수업 슬라이드 원문 · C

int search_binary2(int key, int low, int high)
{
    int middle;
    while( low <= high ){   // 아직 숫자들이 남아 있으면
        middle = (low+high)/2;
        if( key == list[middle] ) return middle;  // 탐색 성공
        else if( key > list[middle] ) low = middle+1;
        else high = middle-1;
    }
    return -1;   // 탐색 실패
}
슬라이드 주석이 서로 바뀌어 있습니다 수업 자료에는 low = middle+1 옆에 ‘왼쪽 부분리스트 탐색’, high = middle-1 옆에 ‘오른쪽 부분리스트 탐색’이라고 적혀 있는데 둘이 반대로 바뀐 것입니다. 찾는 값이 가운데보다 크면 오른쪽(low를 올림), 작으면 왼쪽(high를 내림)이 맞습니다. 코드 자체는 정확하니 주석만 바꿔서 기억하세요.
while(low <= high) “아직 남은 범위가 있으면 계속.” low가 high를 넘어서면 범위가 사라진 것 = 없다는 뜻.
middle = (low+high)/2; “남은 범위의 딱 가운데를 펼쳐 본다.”
key > list[middle] “찾는 값이 가운데보다 크네? 그럼 왼쪽 절반은 볼 필요도 없다.”
low = middle+1; “가운데 바로 오른쪽부터 다시 시작.” 왼쪽 절반이 통째로 사라집니다.
high = middle-1; 반대의 경우. “가운데 바로 왼쪽까지만 보자.”

색인 순차 탐색INDEXED SEQUENTIAL SEARCH

O(m + n/m)

인덱스 테이블을 사용하여 탐색 효율을 높입니다. 주 자료 리스트와 인덱스 테이블은 모두 정렬되어 있어야 합니다. (인덱스 테이블 크기 = m, 주 자료 리스트 크기 = n)

사전 옆면의 ‘ㄱ ㄴ ㄷ’ 홈

두꺼운 사전 옆면에는 ㄱ, ㄴ, ㄷ… 홈이 파여 있습니다. ‘자료구조’를 찾을 때 먼저 ㅈ 홈으로 단번에 점프하고, 거기서부터 한 장씩 넘깁니다. 전화번호부의 색인, 책 맨 뒤의 찾아보기도 같은 원리입니다.

보간 탐색INTERPOLATION SEARCH

O(log n)

사전이나 전화번호부를 탐색하는 방법입니다. 탐색키가 존재할 위치를 예측하여 탐색합니다. 이진 탐색과 유사하나 리스트를 불균등 분할하여 탐색합니다.

‘ㅎ’을 찾는데 가운데를 펼치나요?

사전에서 ‘하늘’을 찾을 때 가운데를 펼치지 않습니다. ㅎ은 끝이니까 뒤쪽 4분의 1쯤을 바로 펼치죠. 이진 탐색이 무조건 반으로 자른다면, 보간 탐색은 값의 크기를 보고 어디쯤 있을지 짐작해서 자릅니다. 자료가 고르게 퍼져 있으면 이진 탐색보다 훨씬 빠릅니다.

5

균형 이진 탐색 트리AVL TREE

O(log n)

이진 탐색 트리는 자료를 어떤 순서로 넣느냐에 따라 한쪽으로 쭉 늘어질 수 있습니다. 그러면 사실상 연결 리스트가 되어 탐색이 O(n)으로 느려집니다. 균형 이진 탐색 트리(AVL 트리) 는 이런 일이 없도록 스스로 모양을 잡습니다.

모빌이 한쪽으로 기울지 않게

천장에 매단 모빌을 떠올려 보세요. 한쪽에만 장식을 잔뜩 달면 기울어집니다. AVL 트리는 모든 노드에서 왼쪽과 오른쪽 높이 차이가 1을 넘지 않도록 유지합니다.

이 ‘높이 차이’를 균형 인수라고 합니다. 모든 노드의 균형 인수가 0, +1, −1 이면 AVL 트리이고, 하나라도 +2 나 −2 가 나오면 AVL 트리가 아닙니다.

(a) AVL 트리
모든 노드의 균형 인수가 0, +1, −1 안에 들어옵니다. 어느 쪽으로도 심하게 치우치지 않아 탐색이 항상 O(log n).
(b) 비 AVL 트리
균형 인수 +2 인 노드가 있습니다. 한쪽으로 기울어져 있어 탐색이 느려질 수 있습니다.
04 / 해싱

해싱과 충돌 해결

지금까지의 탐색은 모두 키 값을 비교했습니다. 해싱은 비교하지 않고 계산해서 바로 자리를 찾아갑니다.

사물함에 번호를 계산해서 넣기

사물함이 7개 있습니다. 학생 번호가 8번인 학생은 어느 사물함을 쓸까요? 8 ÷ 7 의 나머지 = 1. 그러니까 1번 사물함입니다. 찾을 때도 계산만 하면 단번에 갑니다. 하나씩 열어 볼 필요가 없죠.

그런데 1번 학생도 계산하면 1번 사물함입니다. 이미 8번이 쓰고 있는데요. 이걸 충돌(collision) 이라고 하고, 이때 어떻게 할지 정하는 게 충돌 해결책입니다.

해시 함수

탐색 키 → 해시 주소

탐색 키를 입력받아 해시 주소를 만들어 냅니다. 이 주소가 배열로 구현된 해시 테이블의 인덱스가 됩니다. 가장 많이 쓰는 제산 함수는 h(k) = k mod M 이고, 테이블 크기 M은 소수(prime number) 로 고릅니다.

충돌과 오버플로우

다른 키가 같은 주소를 갖는 일

충돌 — 서로 다른 두 탐색키 k1, k2 에 대해 h(k1)=h(k2) 인 경우.
오버플로우 — 충돌이 버켓에 할당된 슬롯 수보다 많이 발생하는 것.
h(k)=k mod M 을 쓰는 한 충돌은 필연적으로 발생합니다.

좋은 해시 함수의 조건

  • 충돌이 적어야 한다.
  • 해시 함수 값이 해시 테이블 주소 영역 내에 고르게 분포되어야 한다.
  • 계산이 빨라야 한다.

해시 함수의 종류

제산 함수
h(k) = k mod M — 나머지를 주소로 씁니다. 테이블 크기 M은 소수(prime number) 로 고릅니다. 가장 많이 쓰는 방식이고, 시뮬레이터도 이 방식입니다.
폴딩 함수
키를 여러 조각으로 잘라 더하는 방식입니다. 조각을 그대로 옮겨 더하는 이동 폴딩과, 접듯이 뒤집어 더하는 경계 폴딩이 있습니다. 자릿수가 긴 키(주민번호, 계좌번호 등)에 씁니다.
슬라이드의 입력 데이터 예시 수업 자료에서는 숫자 대신 단어를 넣는 예도 보여 줍니다 — array, binary, bubble, file, digit, direct, zero, bucket. 선형 조사법 예시에서는 “do”, “for”, “if”, “case”, “else”, “return”, “function” 을 씁니다. 문자열도 숫자로 바꾸면(예: 글자 코드의 합) 똑같이 해싱할 수 있습니다.

충돌 해결 시뮬레이터

수업 슬라이드의 예제 그대로입니다. 테이블 크기 M = 7, 넣을 키는 8, 1, 9, 6, 13. 네 가지 방법이 어떻게 다르게 처리하는지 한 단계씩 보세요.

해결책
단계
0 / 0

0

선형 조사법
충돌이 나면 (h(k)+1) mod M 으로 바로 옆칸을 봅니다. 간단하지만 값들이 한곳에 뭉치는 군집 문제가 생깁니다.
이차 조사법
(h(k)+inc×inc) mod M 으로 h(k), h(k)+1, h(k)+4, h(k)+9 … 를 봅니다. 점점 멀리 뛰어서 군집 문제를 크게 완화합니다.
왜 선형과 이차의 결과가 똑같이 나올까?
시뮬레이터를 돌려 보면 이 예제에서는 두 방법의 최종 테이블이 같습니다. 고장이 아닙니다. 첫 번째 재시도는 inc=1 이라 1×1 = 1 로 선형 조사법과 값이 같기 때문입니다. 이 예제는 모든 충돌이 한 번만에 해결되어 차이가 드러나지 않습니다. 두 번 이상 충돌해야 비로소 갈라집니다 — 선형은 +1, +2, +3 으로 옆으로 기어가고, 이차는 +1, +4, +9 로 점점 멀리 뜁니다. 이중 해싱을 눌러 13이 두 번 충돌하는 장면을 보면 차이를 확인할 수 있습니다.
이중 해싱
오버플로우가 나면 다른 해시 함수를 하나 더 씁니다. 예제에서는 h’(k)=5−(k mod 5) 만큼씩 건너뜁니다.
체이닝
각 버켓에 연결 리스트를 매답니다. 충돌이 나면 노드를 새로 만들어 이어 붙입니다. 고정 슬롯이 없어 오버플로우 자체가 사라집니다.
슬라이드 오탈자 이중 해싱 설명에 h’(k)=5−(5 mod 5) 라고 적혀 있는데, 아래 계산 과정을 보면 h’(k)=5−(k mod 5) 가 맞습니다. 실제로 h’(1)=5−1=4, h’(13)=5−3=2 로 계산되어 있습니다.

06 / 점검

확인 문제

먼저 스스로 답을 생각한 뒤 눌러서 확인하세요.

Q1 순차 탐색에서 탐색 성공일 때 평균 비교 횟수와, 탐색 실패일 때 비교 횟수는 각각 몇 번인가?

성공은 평균 (n+1)/2번, 실패는 n번입니다. 성공은 운이 좋으면 1번, 나쁘면 n번이라 평균을 내면 (n+1)/2가 되고, 실패는 끝까지 다 확인해야만 없다는 걸 알 수 있으므로 항상 n번입니다.

Q2 이진 탐색을 쓰려면 반드시 필요한 조건은 무엇이며, 그 이유는?

자료가 정렬되어 있어야 합니다. 가운데 값과 비교해서 “찾는 값이 왼쪽에 있다/오른쪽에 있다” 를 판단하는 것이 핵심인데, 정렬돼 있지 않으면 그 판단 자체가 불가능하기 때문입니다. 업다운 게임이 성립하려면 숫자가 순서대로 있어야 하는 것과 같습니다.

Q3 크기 7인 해시 테이블에 h(k)=k mod 7 로 8과 1을 넣으려 한다. 무슨 일이 생기며, 선형 조사법은 이를 어떻게 해결하는가?

h(8)=8 mod 7=1, h(1)=1 mod 7=1 로 같은 주소가 나와 충돌합니다. 선형 조사법은 (h(1)+1) mod 7 = 2 번을 확인해 비어 있으면 거기에 저장합니다. 즉 바로 옆칸부터 차례로 빈자리를 찾아 갑니다.

Q4 해시 테이블의 크기 M을 소수(prime number) 로 고르는 이유는?

나머지 연산 k mod M 의 결과가 0 ~ M-1 에 고르게 퍼지게 하기 위해서입니다. M이 예를 들어 10처럼 약수가 많은 수면, 키들이 특정 배수에 몰려 있을 때 같은 주소로 쏠려 충돌이 훨씬 많아집니다. 소수는 약수가 1과 자기 자신뿐이라 그런 쏠림이 잘 생기지 않습니다.

Q5 체이닝이 조사법(선형·이차·이중)과 근본적으로 다른 점은?

조사법은 테이블 안의 다른 빈칸을 찾아 넣습니다. 그래서 테이블이 꽉 차면 더 넣을 수 없고, 값들이 뭉치는 군집 문제도 생깁니다.
체이닝은 각 버켓에 연결 리스트를 매달아 노드를 새로 만들어 이어 붙입니다. 고정된 슬롯 수가 없으므로 오버플로우 문제가 사라집니다.

01 / 목적

이 과제로 무엇을 확인하는가

수업 시간에 안내한 목적 두 가지입니다. 채점의 축도 결국 이 두 가지입니다.

목적 1

선형에서 비선형으로의 확장

1학기 때 학습한 선형 자료구조(배열, 리스트 등)의 한계를 인식하고, 복잡한 다대다(Many-to-Many) 관계를 다루기 위해 비선형 자료구조(트리, 그래프)가 왜 필요한지 연결합니다.

목적 2

알고리즘으로의 브릿지(Bridge)

우리가 설계한 비선형 구조 안에서 데이터를 효율적으로 찾거나 순서를 정하기 위해 탐색(Searching) 및 정렬(Sorting) 알고리즘이 어떻게 작동해야 하는지 논리적으로 추론합니다.

채점자가 실제로 보는 것

조사를 얼마나 많이 했는지는 점수와 관계가 없습니다. 서비스 소개가 길어도 점수는 오르지 않습니다. 조사한 내용을 자료구조·알고리즘의 원리와 얼마나 정확하게 연결했는지만 봅니다.

04 / AI

AI 활용 3단계

이 과제는 생성형 AI로 아이디어와 자료를 얻은 뒤, 그것을 검토하고 고쳐서 제출하는 방식입니다. 아래 순서대로만 하면 규정을 지키면서 점수를 올릴 수 있습니다.

1

재료 모으기 — AI에게 아이디어와 자료를 받는다

다음 장의 프롬프트를 그대로 복사해 붙여 넣으면, AI가 주제 후보·비교표·개념 정리를 만들어 줍니다. 이건 내 답이 아니라 재료입니다.

2

검토하기 — 사실을 확인하고 내 주제에 맞는 것만 고른다

AI는 시간 복잡도나 알고리즘 설명을 틀리게 말할 때가 있습니다. 교과서와 수업 필기로 대조하고, 내 주제와 맞지 않는 내용은 버립니다. 프롬프트마다 AI가 [내가 직접 확인해야 할 것] 목록을 만들어 주도록 해 두었습니다.

3

다시 쓰기 — 내 언어로 옮기고, 마지막에 한 번 더 점검받는다

고른 재료를 보지 않고 내 말로 씁니다. 다 쓴 뒤 P5로 채점기준에 대조하고, P6로 그대로 베낀 문장이 남아 있지 않은지 확인합니다.

해도 되는 것

  • 자료 검색과 전문 자료의 요약
  • 주제 후보와 아이디어를 여러 개 받아 보기
  • 알고리즘 비교표·개념 설명 받기
  • 내가 쓴 글의 사실관계 확인받기
  • 내 논리에서 빠진 부분을 지적받기

하면 안 되는 것

  • AI가 써 준 문장을 그대로 옮겨 적기
  • 항목 전체를 통째로 대신 작성시키기
  • 사실 확인 없이 AI 설명을 그대로 믿기
  • 출처와 AI 활용 범위를 밝히지 않기
결과물 산출에 AI를 활용한 내용을 그대로 작성할 경우, 해당 평가 요소의 최하점이 부여됩니다. AI 답변 중 그대로 베끼고 싶어지는 문장이 나왔다면, 그게 바로 베끼면 안 되는 문장입니다. 읽고 창을 닫은 뒤 내 말로 다시 쓰세요. 그 과정이 이 과제가 평가하려는 능력 그 자체입니다.

01 / 목적

이 과제로 무엇을 확인하는가

수행평가 1이 “관계를 어떻게 표현할 것인가”였다면, 이번에는 “그 안에서 어떻게 빠르게 찾을 것인가”입니다.

목적 1

자료의 특성이 탐색 전략을 결정한다

자료가 정렬되어 있는지, 몇 건인지에 따라 쓸 수 있는 탐색 방법이 달라집니다. 자료를 먼저 분석하고 그에 맞는 방법을 고르는 순서를 익힙니다.

목적 2

배운 이론을 코드로 직접 확인한다

“이진 탐색이 O(log n)이다”를 외우는 것과 100만 건에서 실제로 20번 만에 찾아내는 걸 눈으로 보는 것은 다릅니다. 코드를 돌려 이론과 실제가 맞는지 직접 확인합니다.

수행평가 1과 다른 점

수행평가 1은 구조를 설계하는 과제였습니다. 이번에는 한 걸음 더 나아가 코드를 실행해 결과를 근거로 삼습니다. 실행 결과로 단계를 기록하고(③ 25점), 실측한 비교 횟수로 효율을 비교합니다(④ 25점). 두 항목을 합쳐 50점, 전체의 절반입니다.

부담 없이 하세요

코드는 완성된 것을 그대로 드립니다. 여러분이 할 일은 세 가지뿐입니다. ① 코드에 내 주제의 데이터를 넣고 ② 실행 버튼을 누르고 ③ 나온 결과를 표에 옮겨 적고 해석하는 것입니다. 새로 코드를 짜야 하는 부분은 없습니다. 설치도 필요 없습니다 — 구글 계정만 있으면 Google Colab에서 바로 실행됩니다.

import random, math

def seq_count(data, target):
    for i, v in enumerate(data):
        if v == target:
            return i + 1
    return len(data)

def bin_count(data, target):
    low, high, c = 0, len(data) - 1, 0
    while low <= high:
        mid = (low + high) // 2
        c += 1
        if data[mid] == target:
            return c
        elif data[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return c

    내 주제에 맞는지 내가 판단해야 하는 부분을 목록으로 짚어 줘.

[4] 내 말로 바꿔 써야 할 문장
    내가 그대로 베끼면 안 되는 핵심 문장을 표시해 줘.

중요: 내 보고서에 그대로 넣을 '완성된 문단'이나 '완성된 표'는 만들지 마.
나는 네 답변을 재료로만 쓰고, 최종 결과물은 내가 직접 만들 거야.

이해했으면 "확인했어"라고만 답하고 기다려 줘.
P1 · 양식 1주제 후보와 자료 특성 파악 
[양식 1] 탐구 주제와 자료의 특성

내가 관심 있는 분야: (예 - 도서 검색 / 음원 검색 / 게임 아이템 시세 /
  학생증 조회 / 택배 조회 … 아직 없으면 "아직 못 정했어")

[요청]
1. 이 분야에서 '무언가를 빠르게 찾아내는 문제'가 뚜렷하게 드러나는
   탐구 주제 후보를 3개 제시해 줘.
2. 각 후보마다 알려 줘.
   - 무엇을 키(key)로 삼아 무엇을 찾는지 한 줄
   - 예상되는 자료의 규모 (수십 / 수천 / 수십만 건)
   - 이 자료가 미리 정렬되어 있을 가능성이 있는지
   - 자료가 자주 추가·삭제되는지
3. 각 후보에 어울릴 자료 구조(배열·리스트 / 이진 탐색 트리 /
   해시 테이블)를 이유와 함께 알려 줘.
4. 고등학생이 수업 시간 안에 정리하기 좋은 것을 추천해 줘.

내가 제출할 선정 이유 문장은 쓰지 마.
P2 · 양식 2탐색 방법 비교표 받기 (25점) 
[양식 2] 탐색 알고리즘 선택

내 주제: (          )
자료의 규모: (          )
정렬 여부: (정렬됨 / 정렬 안 됨 / 정렬할 수 있음)
추가·삭제 빈도: (거의 없음 / 자주 있음)

[요청]
1. 순차 탐색, 이진 탐색, 해싱을 표로 비교해 줘.
   표의 열: 사용 조건 / 평균 시간 복잡도 / 최악 시간 복잡도 /
            내 자료에 맞는 정도

2. 내 자료가 '정렬되어 있을 때'와 '정렬되어 있지 않을 때'
   답이 어떻게 달라지는지 알려 줘.
   정렬하는 데 드는 비용(O(n log n))까지 고려하면 어떻게 되는지도
   알려 줘.

3. 가장 적합한 방법 하나를 추천하고, 그 방법이 '오히려 불리해지는
   상황'도 함께 알려 줘.

4. 내가 선택 근거를 직접 쓸 때 반드시 언급해야 할 키워드를
   3개만 알려 줘. 문장으로는 쓰지 마.
P3 · 양식 3코드가 오류 날 때 · 실행 결과 해석하기 
[양식 3] 코드 실행과 결과 해석

내가 넣은 데이터: (코드의 data 부분을 그대로 붙여넣기)
찾으려는 값: (          )
실행 결과: (Colab 출력 화면을 그대로 붙여넣기.
            오류가 났다면 오류 메시지를 그대로 붙여넣기)

[요청]
1. 오류가 났다면 원인이 무엇인지 알려 줘.
   고친 코드 전체를 주지 말고, 어느 줄의 무엇이 문제인지만 짚어 줘.

2. 실행 결과를 보고, 내가 표에 옮겨 적어야 할 항목이
   (단계 / 비교한 값 / 남은 탐색 범위 / 판단) 각각 출력의 어느
   부분에 해당하는지 알려 줘. 표를 대신 채워 주지는 마.

3. 이 결과에서 탐색 범위가 어떻게 줄어들고 있는지,
   내가 스스로 설명할 수 있도록 질문 3개를 던져 줘.

4. 자료에 없는 값을 찾으면 결과가 어떻게 달라질지
   내가 예상해 보게 하는 질문을 하나 해 줘.
   (답은 알려 주지 마. 내가 직접 실행해서 확인할 거야.)
P4 · 양식 4실측 결과를 이론과 맞춰 보기 (25점) 
[양식 4] 실측 결과와 시간 복잡도

내 주제: (          )
내가 고른 탐색 방법: (          )
코드 C 실행 결과: (출력된 표를 그대로 붙여넣기)

[요청]
1. 내 실행 결과에서 이진 탐색의 비교 횟수가 log2(자료 크기)와
   얼마나 비슷한지 확인해 줘. 차이가 있다면 왜 그런지 알려 줘.

2. 순차 탐색의 평균 비교 횟수가 자료 크기의 절반쯤 나오는 이유를
   내가 스스로 설명할 수 있도록 질문으로 짚어 줘.

3. 내가 고른 방법의 최선·평균·최악이 각각 어떤 상황인지,
   내 주제로 예를 들어 설명해 줘.

4. 해시 테이블이 평균 O(1)인데도 항상 최선이 아닌 이유를 알려 줘.

5. '정렬해서 이진 탐색하기'와 '그냥 순차 탐색하기' 중 무엇이
   유리한지 갈리는 기준을, 내가 판단할 수 있도록 질문으로 짚어 줘.
   (한 번만 찾을 때와 여러 번 찾을 때를 나눠서)

6. 마지막에 [내가 직접 판단해야 할 것] 목록을 붙여 줘.

내 실행 결과의 숫자를 네가 지어내지 마. 내가 붙여넣은 것만 써 줘.
P5채점기준표에 내 글을 대조시키기 
아래는 내가 직접 쓴 보고서야. 채점기준에 맞춰 고칠 곳을 찾아 줘.

[채점기준]  (총 100점, 영역명 '탐색 알고리즘 설계')
① 탐색 문제 상황 분석 및 자료 구조 선정 (15점)
② 탐색 알고리즘 선택과 적용 근거 (25점)
③ 탐색 과정의 단계적 표현 (25점)
④ 시간 복잡도 분석과 효율 비교 (25점)
⑤ 탐구 결과의 표현 및 공유 (10점)

[내 보고서]
(여기에 내가 쓴 전문을 붙여넣기. 표는 글자로 옮겨 적기)

[요청]
1. 요소별로 지금 몇 점 수준인지 판정하고, 그렇게 본 근거가 된
   내 문장을 그대로 인용해 줘.
2. 시간 복잡도나 비교 횟수 계산이 틀린 곳이 있으면 반드시 짚어 줘.
3. ③번 단계 표에서 빠진 정보가 있는지 확인해 줘.
   (비교한 값 / 남은 범위 / 판단이 모두 드러나는지)
4. 각 요소를 한 단계 올리려면 무엇을 더 생각해야 하는지 알려 줘.
   완성된 문장이나 표를 대신 만들어 주지는 마.
5. 내가 고쳐야 할 순서를 우선순위 3개로 정리해 줘.
